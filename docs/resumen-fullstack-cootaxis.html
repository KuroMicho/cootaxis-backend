CooTaxis Mocoa — Resumen Fullstack

Sistema contable para la cooperativa de taxistas CooTaxis LTDA, Mocoa (Colombia).
Generado: 6 de julio de 2026  |  Backend: Express + MySQL  |  Frontend: React + Vite

1. Visión general

La aplicación es un sistema contable de oficina para gestionar socios (conductores de taxi), préstamos con amortización francesa, informes financieros y un historial de auditoría inmutable. Está diseñada para ejecutarse en red local con XAMPP (MySQL) y un servidor Node.js en el puerto 5000.

2.1 Stack tecnológico

2.2 Arquitectura

Patrón feature-first: cada módulo tiene routes, controller, model y documentación YAML.

  • features/socios/ — CRUD de asociados
  • features/prestamos/ — Cartera, simulación y cambio de estado
  • features/auditoria/ — Registro inmutable de cambios
  • config/db.js — Pool de conexiones MySQL
  • database/schema.sql — Esquema completo

2.3 Base de datos (3 tablas)

Tabla Propósito Campos clave
socios Taxistas afiliados cédula, cupo (único), placa (única), celular, domicilio, estado ACTIVO/INACTIVO
prestamos Créditos de cartera importe, tasa, cuotas, interés, total_pagar, estado PENDIENTE/PAGADO/MORA, FK → socios
auditoria Log inmutable módulo, acción, descripción, responsable, fecha_hora, entidad_id

2.4 Endpoints API

Método Ruta Descripción
GET /api/health Estado del servidor
GET /api/socios Listar socios
GET /api/socios/:cupo Buscar por cupo
POST /api/socios Crear socio
PUT /api/socios/:cupo Actualizar socio
DELETE /api/socios/:cupo Eliminar socio (bloqueado si tiene préstamos)
GET /api/prestamos Listar préstamos (JOIN con socio)
GET /api/prestamos/:id Detalle + tabla de amortización
POST /api/prestamos Crear préstamo (cálculo francés en servidor)
POST /api/prestamos/simular Simular amortización sin guardar
PUT /api/prestamos/:id/estado Cambiar estado contable
GET /api/auditoria Historial de auditoría (?modulo, ?limit, ?offset)

2.5 Lógica de negocio destacada

  • Sistema Francés: cuota fija, interés sobre saldo decreciente. Calculado en el servidor al crear préstamos.
  • Auditoría automática: cada CREATE/UPDATE/DELETE en socios y CREATE/CAMBIO_ESTADO en préstamos genera un log.
  • Responsable: campos opcionales responsable_nombre y responsable_rol en el body; default "Sistema / Operador".

3.4 Módulos de la interfaz

Panel de Inicio (/)

  • Saludo personalizado con fecha colombiana
  • KPIs estáticos (142 socios, $45.850.000 cartera, $175.000 recaudo) — no conectados al API
  • Descripción de permisos según rol

Gestión de Socios (/socios)

  • Tabla paginada con búsqueda (nombre, cupo, placa) y filtro por estado
  • CRUD completo vía modal + confirmación de eliminación
  • Importación/exportación Excel (ExcelActions)
  • Tarjetas de actividad reciente (últimos 4 préstamos) con enlace a préstamos filtrados

Módulo de Préstamos (/prestamos)

  • KPIs dinámicos: colocación total, vigentes, en mora
  • Tabla con búsqueda, filtro por estado y rango de fechas de desembolso
  • Modal: buscador de socio + simulación francesa + desembolso real
  • Modal de detalle con tabla de amortización completa
  • Cambio de estado inline (PENDIENTE / PAGADO / MORA)

Central de Informes (/informes)

  • Métricas: intereses del mes, cobrado vs pendiente, capital prestado
  • Exportación Excel con 3 perfiles: Administrador, Contador, Socio individual
  • Datos obtenidos de socios + préstamos en tiempo real

Historial de Auditoría (/historial)

  • Tabla cronológica: fecha, módulo, responsable, descripción
  • Filtro por módulo (SOCIOS / PRESTAMOS)
  • Datos mock de respaldo si el API falla
